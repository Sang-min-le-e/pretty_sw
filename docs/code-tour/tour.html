새 개념const 와 final

위젯과 위젯 트리

Flutter에서 화면에 보이는 모든 것(글자, 버튼, 여백, 화면 전체)은 위젯입니다. 위젯은 다른 위젯을 child(하나)나 children(여러 개)로 품어서 나무 모양을 만듭니다. 코드의 괄호 들여쓰기가 곧 화면의 포함 관계입니다.

const 와 final

final은 "한 번 넣으면 다른 값으로 바꿀 수 없는 변수"입니다. const는 그보다 강해서 "앱을 빌드할 때 이미 값이 확정된 것"입니다. 위젯 앞의 const는 Flutter가 그 위젯을 매번 새로 만들지 않고 재사용하게 해서 조금 더 빠릅니다. 붙여도 되는 곳에 안 붙이면 flutter analyze가 알려줍니다.

class / extends

class는 설계도입니다. class A extends B는 "B의 기능을 물려받은 A"라는 뜻입니다. RoutineApp extends StatelessWidget이면 RoutineApp은 위젯으로서 필요한 기능을 전부 물려받고, 자기만의 build만 새로 쓰면 됩니다.

생성자와 { } 이름 있는 인자

클래스 이름과 같은 함수(RoutineApp(...))가 생성자입니다. 객체를 만들 때 불립니다. 괄호 안을 { }로 감싸면 "이름 있는 인자"가 되어 부를 때 ApiClient(baseUrl: '...')처럼 이름을 붙여 넘깁니다. required가 붙으면 꼭 넘겨야 하고, 없으면 생략할 수 있습니다. this.x는 "받은 값을 바로 내 필드 x에 넣어라"라는 줄임말입니다.

@override

부모 클래스(또는 구현하기로 한 인터페이스)에 이미 있는 함수를 "내 방식으로 다시 쓴다"는 표시입니다. 빠뜨려도 동작은 하지만, 이름을 잘못 쓰면 분석기가 잡아주므로 붙이는 게 관례입니다.

build(context)

Flutter가 이 위젯을 화면에 그려야 할 때마다 부르는 함수입니다. 여기서 반환한 위젯 트리가 그대로 화면이 됩니다. context는 "트리 안에서 내 위치"라서, 테마를 찾거나 context.go()로 화면을 옮길 때 씁니다.

StatefulWidget 과 State

스스로 바뀌는 값(타이머, 입력 중인 글자, 로딩 중 여부)이 있는 화면은 두 클래스로 나뉩니다. 바깥 StatefulWidget은 껍데기이고, 실제 값과 build는 State 클래스에 있습니다. setState(() { ... })로 값을 바꾸면 Flutter가 build를 다시 불러 화면을 새로 그립니다. initState는 화면이 처음 생길 때 한 번, dispose는 화면이 사라질 때 한 번 불립니다.

밑줄 _ 로 시작하는 이름

Dart에서 이름이 _로 시작하면 그 파일 밖에서는 볼 수 없습니다(private). _SplashScreenState, _submit, _box가 그 예입니다. "이 파일 안에서만 쓰는 내부 부품"이라는 표시로 읽으면 됩니다.

? ! ?. ?? (null 관련 기호)

String?은 "문자열이거나 null(값 없음)"입니다. ? 없는 타입에는 null이 못 들어갑니다. a?.b는 "a가 null이면 멈추고 null, 아니면 b", a ?? b는 "a가 null이면 b를 대신 써라", a!는 "a는 절대 null이 아니라고 내가 보증한다"입니다(틀리면 앱이 죽습니다).

=> 화살표 함수

(x) => 식은 (x) { return 식; }의 줄임말입니다. 한 줄로 끝나는 함수에 씁니다.

Riverpod Provider

앱 여러 곳에서 같이 쓰는 객체를 만들어 두는 "공용 보관함"입니다. final xProvider = Provider((ref) => 객체)로 만드는 법을 적어두면, 처음 필요할 때 한 번 만들어서 계속 같은 것을 돌려줍니다. 화면에서는 ref.read(xProvider)(지금 한 번 꺼내기) 또는 ref.watch(xProvider)(꺼내고, 바뀌면 다시 그리기)로 꺼냅니다.

< > 제네릭

List<String>은 "문자열이 담긴 리스트", Future<AuthUser>는 "나중에 AuthUser가 나오는 상자"처럼, 꺾쇠 안에 "무엇을 담는지"를 적는 문법입니다. Map<String, dynamic>은 "키는 문자열, 값은 아무 타입"인 사전입니다(서버 JSON이 이 모양으로 들어옵니다).

abstract class / implements

abstract class는 "이런 함수들이 있어야 한다"는 목록(약속)만 있고 내용은 없는 클래스입니다. class B implements A는 "B가 A의 약속을 전부 실제로 구현한다"는 뜻입니다. 화면은 약속(A)만 알고, 실제로 Hive를 쓸지 서버를 쓸지는 B가 정합니다. 그래서 나중에 B만 바꿔 끼우면 화면 코드는 그대로 둘 수 있습니다.

try / on ... catch / finally

try { } 안에서 문제가 생겨 예외(Exception)가 던져지면, 그 아래 줄은 건너뛰고 해당 종류를 받는 on 타입 catch (e) { }로 점프합니다. finally { }는 성공하든 실패하든 마지막에 항상 실행됩니다.

get (게터)

Future<Box<Map>> get _box => ...처럼 get으로 만든 것은 괄호 없이 변수처럼 읽지만, 읽을 때마다 오른쪽 식이 실행되는 함수입니다.

factory 생성자 / fromJson

factory는 "객체를 만드는 방법을 직접 코드로 정하는 생성자"입니다. AuthUser.fromJson(json)은 서버에서 온 JSON 사전을 받아 필드를 하나씩 꺼내 AuthUser 객체를 만들어 돌려줍니다. 앱 안에서는 사전 대신 이 객체를 쓰니 오타를 컴파일러가 잡아줍니다.
